# Мониторинг ошибок приложения

Платформа группирует необработанные ошибки по типу, HTTP-методу и
нормализованному маршруту. Числовые ID, UUID, email и длинные непрозрачные
токены в пути заменяются шаблонами. Текст исключения, query-параметры и тело
запроса в базе не сохраняются.

## Жизненный цикл

- `active` — ошибка обнаружена и требует разбора;
- `acknowledged` — суперадмин принял ошибку в работу;
- `resolved` — исправление выполнено;
- новое срабатывание решённой ошибки автоматически открывает её повторно.

На странице `/system` показаны открытые, повторяющиеся, принятые и решённые
инциденты. Там же доступны действия «Принять» и «Решено». CSV выгружается по
адресу `/system/errors/export`, JSON — `/api/system/error-incidents`.

## Уведомления

После заданного числа повторов платформа создаёт системное уведомление всем
активным суперадминам и отправляет сообщение в общий Telegram-чат, если он
настроен. Cooldown ограничивает частоту повторных уведомлений.

Переменные окружения:

```text
ERROR_MONITOR_ALERT_THRESHOLD=3
ERROR_MONITOR_ALERT_COOLDOWN_MINUTES=60
ERROR_MONITOR_RECENT_HOURS=24
```

## Проверка

```bash
python3 tests/smoke_error_monitoring.py
python3 tests/smoke_app.py
```

PostgreSQL-конкурентность агрегации проверяется в
`tests/smoke_postgresql_concurrency.py`.
